# UC03 审核门户认领申请

**版本**：v1.1（按 B1 SRS 对齐）　**负责人**：A4　**来源**：A3 用例清单、作业 1 的 R03/R05、B1 SRS FR-27/IF-11/DR-09　**优先级**：Must

| 项目 | 规约 |
| --- | --- |
| 主参与者 | 平台管理员（ACT04），须有认领审核权限 |
| 相关参与者 | 申请人（ACT02）接收审核结果；不把申请人画成此用例的审核执行者 |
| 目标 | 核对申请人与目标学者门户的关系，作出可追溯的通过或驳回决定，防止冒领 |
| 触发 | 管理员从待处理队列打开一条认领申请 |
| 前置条件 | 申请由 UC02 建立且处于允许审核的状态；管理员已获得审核权限；申请材料对该管理员可见 |
| 成功后置条件 | 申请状态为 `approved` 或 `rejected`，含审核人、时间、理由/依据、状态变更记录；通过时只授予目标门户管理权，驳回时不授予 |
| 最低保证 | 权限不足、材料不足、并发冲突或服务失败时不授予管理权；申请及已有门户数据不丢失；审核证据不公开展示 |

## 主成功流程

1. 管理员打开待审核申请，平台显示申请编号、目标门户公开信息、申请人标识、佐证材料及历史处理/冲突提示。
2. 管理员核对申请人身份材料、目标门户归属和现有认领状态；必要时按组织确认渠道核实，具体渠道以学校制度与授权为准。
3. 平台提示同名、多机构、已有管理人、重复申请等风险；管理员确认本次决定的目标门户标识，而非仅按姓名判断。
4. 管理员选择“通过”或“驳回”，填写处理理由与依据。平台校验该申请仍处于可决定状态且管理员仍有权限。
5. 若通过，平台把申请置 `approved`，为申请人开通**该目标门户**的管理权限；若驳回，平台置 `rejected` 且不授予权限。驳回后申请人可按 B1 SRS 补证重提；已批准后发生身份争议可标 `disputed` 并撤销错误关联。
6. 平台在同一处理结果中保存审核人、时间、决定、理由、证据引用和状态变更日志，并向申请人展示可见的结果说明。非公开佐证不随结果公开。

## 备选与异常流程

| 编号/接入点 | 条件 | 系统行为与结果 |
| --- | --- | --- |
| A1／步骤 1 | 管理员无审核权限 | 拒绝读取非公开材料和提交决定，记录越权尝试；申请状态不变 |
| A2／步骤 2—3 | 材料不足或同名归属无法判定 | 不通过申请；进入补正/待核验处理路径或记录驳回理由。是否设置独立“补正”状态由状态图与现行制度确定 |
| A3／步骤 3 | 目标门户已有管理人或两人争议 | 暂停直接通过，转人工争议处理；不能静默替换原管理人 |
| A4／步骤 4 | 申请已撤回、已处理或被另一管理员并发处理 | 拒绝第二次决定，展示最新状态；不得重复授予或撤销权限 |
| A5／步骤 4—6 | 审核记录保存、权限授予或通知失败 | 审核状态与权限授予须保持一致；若不能完成一致处理，则不展示“通过成功”，记录失败待恢复。通知失败不应抹掉已保存的审核决定，具体事务/补偿策略由 SRS/SPEC 定义 |
| A6／步骤 4 | 管理员驳回 | 要求填写理由；保存“驳回”，权限不变；申请人可查看对其公开的理由及后续处理入口（若制度允许） |

## 业务规则与数据要求

- BR-UC03-01：只有具有认领审核权限的管理员可以查看非公开佐证并作决定；浏览门户的访客、申请人和普通已认领学者不得代审。
- BR-UC03-02：审核决定必须指向唯一申请编号和唯一目标门户，保留审核人、时间、决定、理由和证据引用。
- BR-UC03-03：认领“通过”与门户管理权限一致；同一申请只能产生一次有效终局决定。冲突时先核验，不自动覆盖既有管理关系。
- BR-UC03-04：审核确认的是门户管理资格，不自动把平台所有同名成果认定为申请人所有。
- BR-UC03-05：状态按 B1 SRS 的 `submitted → verifying → approved/rejected`，申请人可 `cancelled`，批准后争议可 `disputed` 并撤销错误关联；具体补证、申诉和管理权转移制度仍需真实业务方确认。

## 可验收场景

1. **通过**：给定材料完整、无冲突的待审核申请；当有权限的管理员核验并通过；则申请状态为“通过”，申请人仅能管理该目标门户，日志含审核人和理由。
2. **驳回**：给定不满足本人认领条件的申请；当管理员填理由并驳回；则申请状态为“驳回”，申请人不获得管理权限。
3. **并发冲突**：给定两名管理员同时打开同一申请；当其中一人先完成决定；则另一人的提交被拒绝并看到最新状态，不产生第二次终局决定。
4. **已有管理人**：给定目标门户已经认领；当另一申请人提交并进入审核；则管理员不能直接覆盖已有管理人，须走争议核验路径。

## 与后续模型的接口

认领审核活动图应把 UC02 的提交、验证与本用例的审核、通过/驳回连成完整路径；认领状态图明确哪些状态允许审核及终局状态。SRS 的权限、日志、隐私与事务条款应承接上述业务规则。**待确认**：具体身份核验材料、审核部门分工、补正/申诉制度、管理权转移规则；本规约没有把这些推演为现行事实。
