### 导入后的实测观察（供后续修改参考）

1. **分区元素**：`type="Partition"` 的单元格会被 CodeArts 按平台自身的分区样式重绘——列的位置与大小保留（故三条泳道是**竖向**的），但标题栏由平台决定画成**列顶横向条**，我在标签里写的逐字换行（`申<br>请<br>人`）不会生效。若要标题也竖排，需要平台自身的分区方向属性；请见第 5 节。
2. **动作节点的构造型**：活动类图里的动作节点显示 `<<State>>`，因为我沿用了已验证的 `State` 元素类型与构造型。状态机图里这是正确的；活动图/SPEC 流程里严格说应为 `<<Action>>` 或省略。属外观问题，不影响图意与追溯，**不强制重导**。
3. **浏览器渲染要求**：CodeArts 的 SVG 把标签放在 `<foreignObject>` 里，并附一个 `[Not supported by viewer]` 的 `<text>` 兜底。因此 rsvg/cairosvg 之类严格渲染器会画成占位文字，**必须用浏览器内核**（`export_svg_png.py` 用无头 Chrome）。

## 5. 导入后需要人工确认的点（重要）

这三个形态的图形并非全部都能从你的样本导出里「原样克隆」，因此有若干处需要你在 CodeArts 中肉眼确认：

| 元素 | 来源 | 需要确认什么 |
| --- | --- | --- |
| 状态（圆角矩形） | 克隆自样本「状态机图」的 State 对象，**已验证形态** | 正常 |
| 初始伪状态（实心圆） | 克隆自样本的 `shape=startState`，**已验证形态** | 正常 |
| 转移（箭头＋文字） | 克隆自样本的 transition 对象，**已验证形态** | **转移上的守卫文字是否显示**。样本里的转移原本没有标签，标签显示未经验证；若不显示，在 CodeArts 里逐个补填（内容见第 7 节清单） |
| 终止伪状态（圆环） | `shape=endState`（draw.io／mxGraph 的 UML 名称，与已验证的 `startState` 配对） | 是否渲染为圆环；若显示异常，从工具箱重新拖一个「终止」节点替换 |
| 判定节点（菱形） | `rhombus`（mxGraph 核心图形） | 是否渲染为菱形 |
| 分区（申请人／平台系统／授权管理员） | `type="Partition"` 的普通矩形（整列背景 + 标题块），不依赖 `shape=swimlane` 或任何方向样式键 | **已核对：列为竖向三列**。标题栏由平台画成列顶横向条，标签中的逐字换行被平台忽略——若需竖排标题，见第 3 节观察 1 与第 5 节 |
| 动作节点（活动图） | 复用样本的圆角矩形样式，元素类型标为 Action | 正常；若类型被平台改写为 State，图形外观不变，不影响可读性 |

另外两点：

- 页面上所有节点均已在设计坐标内排好（不重叠、在页内、在泳道内），但 **mxGraph 的实际走线由平台路由器决定**，个别连线可能需要手动拖一下走线点。
- 内置图类型 UUID 取自你样本 `1_meta/3_view_types.json`：活动图 `ff1ee59d-ac06-11e8-9e12-0242ac117104`，状态机图 `ff1ee701-ac06-11e8-9e12-0242ac117104`，父类型 `ff1ee18c-ac06-11e8-9e12-0242ac117104`。

## 7. 若需在 CodeArts 中手工补标签：守卫条件清单

活动图（认领审核）：
`开始 → 定位目标学者门户 → 填写身份信息与佐证并提交 → 校验（否：返回具体错误/既有申请编号 → 修正后重新提交；是：保存申请编号与提交快照 submitted）→ 核验证据与归属 verifying → 证据足够且归属可判定（否：记录驳回理由 rejected；是：已有管理人或并发争议）→ 争议（是：暂停直接通过并转争议核验 → 驳回；否：有权限管理员审核申请与版本 → 批准？）→ 批准（否：驳回；是：原子记录 approved 与目标门户管理权限）→ 通知申请人`
终止：驳回后通知可见结果、允许按 B1 SRS 补证重提；批准后通知并允许管理目标门户。

采集任务状态图：
`初始 → queued（创建合法任务）→ running（管理员启动/调度启动）→ succeeded（全批次完成且满足成功口径）／failed（源站/解析/写入失败）／stopped（管理员停止）；failed → retrying（重试未满 3 次）→ running（退避结束，幂等续跑）／stopped（管理员停止）；failed → 终止（放弃或达到上限）；succeeded、stopped → 终止`

认领申请状态图：
`初始 → submitted（UC02 保存申请编号与材料引用）→ verifying（进入核验队列）；submitted／verifying → cancelled（申请人取消 / 申请人取消且尚未终局处理）；verifying → approved（UC03 审核通过并授目标门户权限）／rejected（UC03 驳回并记录理由）；approved → disputed（批准后出现身份争议，撤销错误关联）；rejected → submitted（申请人补证重提，新处理轮次）；cancelled → 终止`
