# UC01 管理数据采集任务

**版本**：v1.1（按 B1 SRS 对齐）　**负责人**：A4　**来源**：A3 用例清单、作业 1 的 R01/R03/R04/R06/R08、B1 SRS FR-25/26、IF-12、DR-09　**优先级**：Must

| 项目 | 规约 |
| --- | --- |
| 主参与者 | 平台管理员（ACT04） |
| 辅助参与者 | 外部数据源（ACT05，仅对已获许可且确实接入的来源成立） |
| 目标 | 对合法来源创建、执行、查看、重试或停止采集任务，将可用成果元数据按来源留痕后纳入候选/入库流程 |
| 触发 | 管理员选择“新建/执行采集任务”，或对已有失败任务发起重试 |
| 前置条件 | 管理员已获任务管理权限；目标源是公开、已授权或课程提供的模拟数据；该源的获取方式、许可与字段映射已登记。定时触发机制尚待 SPEC 决定 |
| 成功后置条件 | 任务状态为“成功”；记录执行时间、来源、检索范围、获取数、有效数、去重数、入库/待核验数及日志；可用记录保留原始来源和字段级溯源 |
| 最低保证 | 失败/停止时记录原因和已处理数量，不把失败写成“零结果”；未经授权的来源不启动；原始记录不因去重被无痕覆盖 |

## 主成功流程

1. 管理员选择已登记的数据源，填写采集范围、成果类型、执行方式和更新规则；平台显示来源许可、预期字段及上次执行记录。
2. 平台校验权限、来源可用性和任务配置；保存任务为“待执行”，生成任务编号与配置快照。
3. 管理员启动任务；平台记录“运行中”、开始时间和执行者。
4. 平台从该公开或授权来源获取元数据；逐条记录源标识、源 URL、获取时间和原字段。原站全文仅保留合法公开入口，不复制收费或无授权全文。
5. 平台按成果类型解析与标准化字段，标注缺失项和疑似机构/作者歧义。DOI、关键词等非必填字段缺失时保留空值及“待核验”，不凭空补值。
6. 平台进行候选去重与消歧，保留“原始记录—规范化记录—合并/关联判断”的可追溯关系；不能确认的候选留在待核验状态。
7. 平台写入满足已定规则的成果记录，并更新任务计数与处理日志；展示本次覆盖范围和来源。
8. 全部计划内批次处理完毕且无阻断性错误，平台将任务标为“成功”，记录完成时间并向管理员展示汇总。

## 备选与异常流程

| 编号/接入点 | 条件 | 系统行为与结果 |
| --- | --- | --- |
| A1／步骤 2 | 来源未获许可、权限不足或配置不合法 | 阻止启动，指出具体原因；任务保持“待执行”或配置草稿，不产生采集请求 |
| A2／步骤 4 | 源站超时、拒绝访问或接口报错 | 记录错误类型和已处理数量；任务转“失败”；管理员可按已定重试策略发起“重试”，不得显示为来源零收录 |
| A3／步骤 4 | 合法查询成功且返回 0 条 | 任务可记“成功”，本次获取数为 0，并显示“本次查询明确零结果”及查询范围；不能推断源站或机构无成果 |
| A4／步骤 5—6 | 字段不完整、同名、重复或归属不确定 | 原记录留痕；可用字段保留，待核验候选不直接作为已确认成果发布；后续人工处理路径由 SPEC 细化 |
| A5／步骤 3—7 | 管理员请求停止 | 平台停止后续批次，任务转“已停止”；记录停止人、时间、已处理数；未完成部分不标成功 |
| A6／步骤 3—7 | 重试请求或系统重试 | 从“失败”转“重试”，记录次数与原因，再进入“运行中”；按 B1 SRS 初版最多重试 3 次，退避间隔写入任务配置；重复批次幂等，不重复入库 |
| A7／步骤 4—7 | 部分批次成功、其余批次失败 | 保留每批计数与错误；总任务不得无说明地标“成功”，最终成功/失败口径和续跑策略由 SPEC 明确 |

## 业务规则与数据要求

- BR-UC01-01：来源必须有可核对的公开/授权依据；知网等收费库不作为未经授权的自动采集源。
- BR-UC01-02：任务状态至少覆盖“待执行、运行中、成功、失败、重试、已停止”；事件与转移须与课程要求的采集任务状态图一致。
- BR-UC01-03：任务结果“获取 0 条”和“查询/处理失败”是不同事实，前端与日志均须区分。
- BR-UC01-04：模型和合法导入路径按 B1 SRS 支持七类成果；同一成果多来源可关联，但应保留各来源原始值和合并判断。具体源是否提供软著、课程材料、未发表手稿，以及能否公开，须逐项核验。
- BR-UC01-05：记录来源 URL、源标识、获取时间、字段来源、核验状态、任务编号；字段可空性与去重阈值由数据字典和 SPEC 定义。
- BR-UC01-06：B1 SRS 将初版重试上限定为 3 次，这是设计规则，不是已实测的来源行为；任务状态与批次的新增/更新/跳过/失败计数须与 FR-25/26 一致。

## 可验收场景

1. **正常采集**：给定一个有许可的测试源且返回 B1 七类中任一适用类型的成果数据；当管理员运行任务；则任务最终为“成功”，每条入库/待核验记录可追溯源 URL、获取时间和任务编号。类型模型支持七类不等于每个来源都实际返回七类。
2. **失败区别于零结果**：给定源站超时；当任务执行；则状态为“失败”、有错误日志，界面不得显示“该源无成果”。
3. **合法零结果**：给定源站成功返回空集合；当任务完成；则状态可为“成功”，获取数为 0，页面说明本次查询范围。
4. **缺失 DOI**：给定题录没有 DOI；当清洗；则 DOI 为空并标记核验状态，不自动生成伪 DOI，也不因此丢弃记录。

## 与后续模型及 SPEC 的接口

采集状态图负责细化 BR-UC01-02 的合法转移；数据清洗、去重/消歧、增量更新 SPEC 负责步骤 5—7 的可执行规则。**仍待业务/技术核验**：具体源及许可、定时调度方式、部分成功口径、退避间隔、管理员角色粒度。B1 SRS 已定义“最多 3 次”为本版设计上限，不能再写成未定义，也不能冒称运行测量结果。
