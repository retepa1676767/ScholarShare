## 1. 角色卡（推演输入）

> **说明**：分工文档引用的《作业1-2-合并执行方案.md》（方法、模板、红线所在文件）未在当前目录，角色卡由 B5 依据《作业1-2-分工与交付物规划.md》§0/§1/§3、A4 失败清单引用内容、B2 桌面研究（见用户故事索引）上下文**自建**。如正式角色卡后补，以正式卡为准并需重跑推演、追加留痕行。

### 教师角色卡

- **身份**：学院教师，兼具科研工作者与成果被展示方双重角色。
- **目标**：署名真实不被冒用、个人成果页自动完整、考核材料可一键取用。
- **痛点**：B2 桌面研究（2026-10-09）显示教师主页平台"有壳无数据"——抽样 3 位软件学院教师（罗川/张梦豪/黎立）论文栏全部为空，逐条录入成本高是维护率低的直接根因。
- **行为假设**：不主动维护、时间碎片化、对"被动等待流程"敏感、对署名排序与真实性高度关注（答辩常问点）。

### 平台管理员角色卡

- **身份**：学院教务 / 科研秘书或平台运营人员。
- **目标**：对外展示内容合规（不实 / 涉密 / 侵权零发生）、存量数据完整可检索、一切争议操作可追溯。
- **痛点**：两级审核后管理员仍是最终责任人；认领、删除等操作存在争议可能，需人工裁定。
- **行为假设**：操作必须留痕、理由必填、倾向最小权限与可逆操作（下架可恢复、删除走软删除）。

## 2. 教师需求推演清单（T-01 ~ T-10，标注推演 ⚠️）

> ⚠️ 以下全部为推演条目，非一手调研结论。"状态建议"仅为 AI 初判，最终优先级由 B5 裁定（§4）。

| 编号 | 推演需求 | 推演动机 | 状态建议（AI 初判） | 备注 |
| --- | --- | --- | --- | --- |
| T-01 | 审核署名含本人的学生成果（通过 / 驳回+理由） | 署名真实性是教师第一关切；未经确认不得对外展示 | 已覆盖 US-06 | Must |
| T-02 | 批量导入论文成果（BibTeX / 知网导出格式） | 逐条手工录入是主页空壳的直接根因 | 已覆盖 US-09 | Should |
| T-03 | 认领他人代录的、署名含本人的成果 | 把维护成本降到一次点击 | 已覆盖 US-08 | Should |
| T-04 | 成果自动归集到个人主页，无需手工整理 | 主页的价值在于"自动完整" | 部分覆盖（US-08 + US-09 两条路径） | Should |
| T-05 | 按"我指导的学生"聚合查看成果汇总 | 导师需要了解学生产出 | 疑似超范围 | 依赖"师生关系"数据模型，平台本期无此模型 |
| T-06 | 导出个人成果清单（CSV，用于年度考核填报） | 学院考核每年需填报，软著/获奖等成果官方渠道查不到 | 建议新增 Should | 轻量导出成本低，与 A4 失败清单呼应 |
| T-07 | 驳回时强制学生补充指定佐证材料 | 驳回后学生不知道该补什么 | 疑似伪需求 | 驳回理由 + 修改重提已是完整闭环 |
| T-08 | 署名相关成果变动时收到通知（学生新增/修改署名） | 署名被单方面变更是高风险事件 | 部分覆盖（US-06 提交触发）；建议扩展到 US-10 重大变更 | Should |
| T-09 | 论文成果一键跳转 DOI 原文 | 核对真实性、便于引用 | 已覆盖（US-02 论文字段含 DOI） | 低成本 |
| T-10 | 查看自己成果的浏览 / 下载统计 | 了解学术影响力 | 疑似超范围 | 统计属平台运营范畴，非成果管理核心诉求 |
